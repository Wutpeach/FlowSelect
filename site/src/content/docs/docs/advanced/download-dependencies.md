---
title: 下载依赖与自动准备
description: 理解 Ameow 首次处理网页下载时为什么可能出现准备阶段，以及用户应该如何处理。
---

某些网页下载能力需要额外组件参与解析、下载或转换。Ameow 会尽量自动准备这些能力，所以你可能在首次下载或升级后看到“准备中”持续一段时间。

看到“准备中”时先不要手动安装工具。先等一小段时间，再用公开链接测试，最后才考虑重启或升级。

## 先运行只读诊断

打开 **设置 → 系统与支持 → 只读诊断**，可以查看当前应用实际观察到的运行时、输出目录、浏览器扩展连接和下载队列信息。这个自检只读取当前状态；它不会下载或安装组件、创建目录、修改设置、重试或取消任务，也不会改变浏览器扩展连接。

报告会区分“已配置”“已观察到”和“已探测”的信息。看到 `未知` 或“未验证”不代表组件一定坏了，只代表 Ameow 没有通过安全的只读方式证明该项状态。文件存在本身也不等于工具可以正常运行。

输出目录的写权限使用不会改动文件的系统权限检查。即使权限被授予，也不代表 Ameow 已经证明可以在该目录创建真实文件或成功完成下载。

## 你会看到什么？

常见现象：

- 第一次下载某类网页内容时准备时间更长。
- 队列显示准备中，但还没开始下载。
- 下载后进入转换中。
- 升级版本后，某些能力需要重新准备。

这不一定是错误。先判断它是正常准备，还是长期卡住。

## 正常准备和异常卡住怎么区分？

| 现象 | 更可能是 | 你应该做什么 |
| --- | --- | --- |
| 首次使用，准备一段时间后继续下载 | 正常准备 | 等待完成 |
| 多个公开链接都长期准备中 | 依赖准备或网络异常 | 重启 Ameow，再换公开链接测试 |
| 只有某个站点准备中 | 站点规则、登录态或链接问题 | 使用扩展发送，检查站点支持 |
| 下载完成后转换较久 | 格式处理 | 等待转换结束再使用文件 |

## 用户需要手动安装什么吗？

普通用户通常不需要手动安装命令行工具。Ameow 的目标是尽量由应用自己管理需要的下载和处理能力。

如果文档或 Release Notes 没有明确要求，不建议你自行修改系统 PATH、替换内部工具或手动下载不可信组件。

## 这些依赖会保存在哪里？

这些自动准备的依赖不是你下载的图片或视频文件，也不会放进当前输出文件夹。它们是 Ameow 自己使用的运行时组件，会保存到 Ameow 的用户数据目录下。

在 Windows 上，即使使用便携版，常见位置也是：

```text
%APPDATA%\Ameow\runtimes\
```

里面可能包含 `yt-dlp`、`gallery-dl`、`ffmpeg`、`deno` 等组件。下载过程中的临时压缩包会先放在系统临时目录，安装和校验完成后会清理。

如果删除 `runtimes` 目录，Ameow 后续需要这些能力时会重新准备。已经下载完成的媒体文件不受这个目录影响，它们仍然在你设置的保存位置。

抖音视频下载使用通用的 `yt-dlp` 能力，不再需要单独的抖音下载器运行时准备阶段。

## 长时间准备中怎么办？

按顺序处理：

1. 等待一小段时间，确认不是首次准备。
2. 检查网络是否能访问该站点。
3. 用一个公开、无需登录的链接测试。
4. 重启 Ameow。
5. 升级到最新稳定版。
6. 如果内容需要登录态，通过浏览器扩展发送任务。

如果公开链接也长期准备中，记录当前版本、平台和链接类型，后续反馈问题时会更容易定位。

## 和下载失败的关系

准备阶段失败只是下载失败的一种。排查时先判断任务状态：完全没出现、一直准备中、明确失败、完成但找不到文件。不同状态的处理方式不同。

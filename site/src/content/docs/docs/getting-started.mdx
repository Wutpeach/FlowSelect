这篇文档只做一件事：帮你确认 Ameow 已经能正常工作。先跑通桌面端，再考虑浏览器扩展和高级设置。

<Aside type="tip" title="只想第一次跑通？">
	准备一个本地测试文件和一个公开网页链接。不要一开始就测试会员、地区限制、登录权限或年龄验证内容。
</Aside>

## 1. 安装并启动

<Tabs>
	<TabItem label="Windows">
		1. 大多数用户下载 Installer EXE 后双击运行。
		2. 如果下载的是 Portable ZIP，先完整解压，再运行解压目录里的 Ameow。
		3. 启动后，桌面边缘应该出现一个小型悬浮窗口。
	</TabItem>
	<TabItem label="macOS">
		1. 打开 DMG。
		2. 把 `Ameow.app` 拖到 `Applications`。
		3. 从 `Applications` 启动 Ameow。
		4. 如果系统提示无法验证开发者，右键 `Ameow.app`，选择“打开”。
	</TabItem>
</Tabs>

[截图：Ameow 主悬浮窗口首次启动后的空闲状态，窗口停靠在桌面边缘]

成功状态：你能看到一个常驻桌面边缘的小窗口。它是接收文件、文件夹和链接的入口，不是传统的大型主窗口。

## 2. 完成第一次保存

<Steps>
1. 在桌面、资源管理器或 Finder 里选中一个测试文件。
2. 把文件拖到 Ameow 悬浮窗口上。
3. 松开鼠标。
4. 从 Ameow 打开当前输出目录。
5. 确认刚才的测试文件已经出现在输出目录里。
</Steps>

[截图：把一个本地文件拖入 Ameow 悬浮窗口时的接收状态]

[截图：Ameow 输出目录中出现刚刚收集的文件]

成功状态：

- 文件会被移动到当前输出目录。
- 原文件不再保留在原来的位置。
- 默认输出目录通常是 `Desktop/Ameow_Received`。

<Aside type="caution" title="文件夹的含义不同">
	拖入文件会移动文件；拖入文件夹会把这个文件夹设为新的输出目录，不会移动整个文件夹。找不到结果时，优先从 Ameow 打开“当前输出目录”。
</Aside>

## 3. 测试一个公开链接

第一次测试链接时，先用公开页面或公开媒体链接。

<Steps>
1. 在浏览器里复制一个公开图片链接、视频链接或支持站点页面链接。
2. 回到 Ameow 悬浮窗口。
3. 按 `Ctrl+V`；macOS 使用 `Cmd+V`。
4. 观察窗口中的任务反馈。
5. 完成后，从 Ameow 打开当前输出目录确认文件。
</Steps>

成功状态：

- 链接可处理时，任务会进入准备、下载或转换流程。
- 完成后，文件会写入当前输出目录。
- 如果链接无效、不支持或缺少权限，任务可能失败。

如果公开链接能跑通，说明桌面端基础流程已经正常。

## 4. 什么时候安装浏览器扩展？

桌面端可以独立使用。浏览器扩展是可选增强，不是第一次启动必需项。

建议在这些情况下安装扩展：

- 你主要下载网页视频。
- 网页在浏览器里能播放，但复制链接后 Ameow 失败。
- 某些站点需要登录态、Cookies、会员权限或页面上下文。
- 你想从扩展弹窗里的“当前页面资源”选择视频、音频或图片。

最短步骤：

<Steps>
1. 下载同版本的 `Ameow_<version>_browser_extension.zip`。
2. 解压 zip。
3. 在 Chrome 或 Edge 的扩展管理页开启开发者模式。
4. 点击 `Load unpacked`，选择解压后的扩展目录。
5. 启动 Ameow 桌面端，再打开扩展弹窗，确认显示 `Connected`。
</Steps>

完整说明见 [浏览器扩展](../browser-extension/) 和 [安装扩展](../extension/install/)。

## 常见第一次失败

### 看不到悬浮窗口

先确认 Ameow 已经启动。Windows 可以从开始菜单重新打开；macOS 请确认应用已经拖入 `Applications`。如果 macOS 阻止启动，按“右键打开”或系统设置放行。

继续处理：阅读 [macOS 首次启动](../troubleshooting/macos-first-run/)。

### 拖入文件后找不到结果

从 Ameow 打开当前输出目录。不要只看默认目录，因为拖入文件夹会切换输出目录。

继续处理：阅读 [输出目录](../desktop/output-folder/) 和 [找不到文件](../troubleshooting/missing-files/)。

### 粘贴链接没有反应

先确认链接本身可以在浏览器中打开。需要登录态的内容建议通过浏览器扩展发送。仍失败时按 [下载失败](../troubleshooting/download-failures/) 的排查树处理。

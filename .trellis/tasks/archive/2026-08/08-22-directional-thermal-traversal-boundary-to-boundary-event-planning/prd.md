# Localized Boundary-Interaction Response + Subordinate <=12px Halo (Architecture Repair)

## Goal

Plan one coherent, renderer-local visual response in which the **existing accepted Thermal
frontier** interacts with a localized segment of the **real rounded panel boundary**, and that
same localized interaction leaks outward as a **subordinate, compact halo**. The plan consumes
only signals that already exist in the accepted HEAD checkpoint; it introduces no new energy,
topology, or time authority.

This is a bounded architecture repair of the planning artifacts. It does not re-plan MR9 as a
directional traversal event, and it does not resurrect the rejected Unified Boundary candidate.

## Scope

- Active phase returns to: accepted Thermal field/shared energy + real 200x200/r16 boundary
  geometry -> **localized boundary-interaction response** -> **subordinate <=12px halo**.
- Accepted baseline is Git HEAD (`4db7722`, branch `motion/mr9-fullscreen-activation-fx`).
  The dirty Unified Boundary diff in the worktree is **rejected/frozen evidence only** and is
  never a baseline.
- The boundary response and halo consume **one already-existing zero-capable contact/frontier
  scalar** from HEAD (`capture` / `contact` = `boundaryBand * warm`), projected outward through
  the accepted rounded SDF geometry.
- Planning only. No production/test edits, no implementation, no shader code, no visual tuning,
  no captures, no task start, no commit, no archive, no Architecture PASS.

## Requirements

- Boundary response must be **localized and visibly broken** at every phase: it may never form a
  full or near-complete perimeter, at any activation age or any interior state (including a
  broadly warm panel).
- The boundary interaction must be **detached-free**: it derives only from the existing accepted
  frontier/contact scalar (`warm`, `capture`, `contact`, `contact2` family) and the accepted
  rounded SDF (`boundaryBand`). It must not be relabeled absolute shared energy and must not add
  thresholds that merely re-label absolute energy.
- The halo is **only outward projection/leakage** of that chosen localized interaction. It uses
  the same Thermal palette/material language, has analytic compact support of at most 12 CSS px,
  and is **exactly zero in the outermost 2px** on all four sides and all four corners.
- One `ExpandedPresentationSurface`, one canvas, one WebGL program, one draw, one
  runtime/frame-time authority. No texture, framebuffer, second renderer, second scheduler, or
  second energy/topology/time authority.
- Accepted interior Thermal material and accepted Refraction direction/identity/gating stay
  **locked and equivalent**; mode-off remains the accepted HEAD fallback (pixel/resource
  equivalent).
- Geometry truth stays 228x228 outer domain, 200x200/r16 real panel at (14,14), 14px transparent
  gutter.
- Clean-room route; no Paper processed morphology, palette, object geometry, or derivative
  implementation enters the candidate.
- Actual `ExpandedPresentationSurface` WebGL compile/link is a hard evidence gate; a copied
  standalone harness is auxiliary only.

## Deferred / Future (PARKED — not in this phase)

The **Directional Thermal Traversal / Entry -> Propagation -> Exit** proposal is **parked as a
future redesign candidate**. It is explicitly removed from current requirements, candidate
design, implementation scope, acceptance gates, and requested Architecture decisions. Parked
elements include:

- new `tau` / traversal event contract;

These are closed for this phase and may only return through a new, explicitly authorized task.
